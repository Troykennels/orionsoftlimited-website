ORION MEET - OWNER SETUP

Staff Office > Meetings > Start team huddle / Schedule meeting.
Private calls: People > choose a colleague > Video / voice call.
Internal meetings do not require downloads or external meeting links.
Camera is enabled by default; users can select voice only before joining.
This implementation supports SIX active participants. Larger organisation
meetings need an SFU and load testing before they can be offered to customers.

Controls: mute, camera, share screen, leave and host end for everyone.
Only invited staff can join a private meeting. Everyone meetings admit active
company staff. The owner uses their linked Staff Office. Content managers do
not gain staff access.

RECORDING
Host only; every participant must explicitly agree before joining.
All participants see the recording indicator. Stop recording before admitting
new participants. Stop, then Download meeting recording. The file mixes voices
and the video grid. Files stay on the host's device; there is no cloud archive.
Recording stops at 30 minutes or 256 MB. Use a current supported browser.
Test target mobile devices separately; screen capture differs by browser.

NETWORK CONNECTIONS - NO NEW CARD REQUIRED
Orion Meet now includes a compatibility media relay on the EXISTING website API.
No Cloudflare account, PayPal or new provider card is required for this path.
Direct WebRTC remains preferred; when direct media cannot flow, the office relay
carries video and speech over authenticated secure WebSockets (HTTPS/TLS).

Both people must REFRESH the portal after this release, leave any old call and
join the SAME meeting from Meetings or the call invitation. One person starts a
meeting; the other chooses Join in portal. Starting two separate meetings will
show two self previews because neither person joined the other's meeting.
A one-person room now explains that it is waiting for someone else.

The participant tile shows Direct connection or Office compatibility connection
only when media arrives. Interrupted connections retry automatically. The
compatibility path uses smaller JPEG video frames and 16 kHz speech audio to
prioritise connectivity. It has lower video quality than direct WebRTC and uses
your existing Railway hosting bandwidth. This is not unlimited free bandwidth.
Current rooms still support SIX people. Larger meetings require an SFU and load
and real-device testing before being sold or presented as supported.

Office relay endpoints are private: an existing invited, active participant
obtains a 45-second, single-use connection ticket. Origins, membership, packet
size and rates are checked. Redis pub/sub supports multiple API processes.
Media packets are relayed in memory, not saved as recordings or logged. TLS
protects transport; the Orion server handles compatibility packets, so this
mode should not be advertised as end-to-end encrypted.

Readiness is reported at /api/public/health under calling.officeRelayReady.
The server attaches the WebSocket listener at /api/staff/call-media; anonymous
upgrades must be rejected. CALL_OFFICE_RELAY_URL is optional if the website API
keeps its current Railway domain. Extra frontend domains need explicit
CALL_OFFICE_RELAY_ORIGINS entries. WSS must point directly to the API host,
not through a hosting proxy that does not support WebSocket upgrades.

The earlier Cloudflare setup is OPTIONAL. Do not enter billing details unless
you choose that provider later. Existing TURN environment adapters remain
available for an optional future quality/scale upgrade. They are not required
for the in-house compatibility connection.

LIGHT MODE
Staff header > Colour mode > Light / Dark / System. Saved per browser. System
follows the device appearance. Forms, dialogs and sign-in share the palette.

SOCIAL STUDIO
Admin > Social Media Content. Campaigns, draft/ready/published/archive states,
caption preview, search, filters and due queue. Stale edits cannot overwrite
newer team changes. Published posts require the actual social post URL.
This planner DOES NOT automatically publish to social networks. That requires
approved OAuth connections to each platform. Content-manager permissions remain
restricted to their existing communications and assigned-client access.

Notifications use browser push and existing jobs. Device permissions and quiet
hours control delivery and sound; audible delivery is not guaranteed everywhere.
